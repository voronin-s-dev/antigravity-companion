# Antigravity Companion: Project Guidelines & Rules

Данный файл содержит обязательные правила для работы с проектом **Antigravity Companion**.

---

## ⚡ Оптимизация токенов и лимитов (Token Economy)

Исторический аудит показал: за первые 4 сессии проект потребил **~257 млн токенов**, из которых 99.85% пришлись на повторное чтение контекста сверхдлинных сессий ($O(N^2)$ сложность).

### Строгие правила сохранения квот:
1. **Сессионный потолок (Session Ceiling — максимум 40 шагов)**:
   - Если количество итераций агента в текущем чате приближается к **35–40 шагам** (или контекст превышает 50–70k токенов), агент **ОБЯЗАН**:
     1. Зафиксировать прогресс в `ACTIVE_STATE.md`.
     2. Сделать коммит в Git.
     3. Предложить пользователю запустить `/handoff` или начать чистую сессию.
   - Запрещено тянуть бесконечные сессии на 200–700 шагов — это сжигает миллионы токенов на каждом микрошаге!
2. **Изолированный headless-перевод (Zero-Context Dictionary)**:
   - **ЗАПРЕЩЕНО** читать или вручную редактировать `localization/dictionary_ru.json`.
   - Для добавления переводов:
     1. `npm run harvest` — сбор непереведенных строк в `localization/untranslated_queue.json`.
     2. Создать временный файл `localization/translations_to_merge.json` с новыми парами `{ "en": "ru" }`.
     3. Запустить `npm run merge` — скрипт сам сольет словарь, проверит валидность (`npm test`) и применит hot-reload.
3. **Мгновенная CDP-диагностика без scratch-скриптов**:
   - Вместо генерации временных WebSocket-скриптов для инспекции окна Antigravity:
     * Запуск общего среза: `npm run doctor:cdp`.
     * Вычисление любого выражения в окне: `node bin/cdp_doctor.js --eval "document.title"`.
4. **Делегирование черновой работы субагентам (`invoke_subagent`)**:
   - При сложных экспериментах с DOM, отладке стилей или парсинге вызывать субагентов (`invoke_subagent`). Черновые шаги субагента остаются в его изолированном контексте, а в основной диалог передается лишь готовый 3-строчный результат.
5. **Точечные (хирургические) правки**:
   - Использовать `replace_file_content` только для минимального диапазона строк.
6. **Краткость ответов**:
   - Не цитировать портянки JSON, дампы DOM или логи. Выдавать только ключевую суть.

## 🛠️ Рабочий процесс разработки

### Добавление новых строк перевода
1. Поиск: проверить наличие строки через `grep_search` в `localization/dictionary_ru.json`.
2. Добавление:
   - Создать `localization/translations_to_merge.json` с новыми фразами.
   - Запустить `npm run merge`.
   - Всё остальное (тесты, слияние, hot reload) выполняется автоматически.

### Экспресс-диагностика UI и CDP
- Общая проверка окружения: `npm run doctor`.
- Глубокая проверка Electron/CDP: `npm run doctor:cdp`.
- Однострочный запрос к DOM: `node bin/cdp_doctor.js --eval "селектор или js"`.
- Горячее обновление: `npm run reload`.

### Работа с виджетом лимитов
- Исходный код панели: `limits_widget/inject_panel.js`.
- Все селекторы и стили должны быть изолированы префиксом `#agy-limits-` или `.agy-`, чтобы не конфликтовать с нативным CSS Antigravity.
- Всегда сохранять поддержку тикающего тултипа с отсчетом секунд (`#agy-limits-tooltip`) и стационарного hover-бокса кнопки перезагрузки.

## 📦 Архитектура дистрибутива

- Все пути должны определяться динамически относительно корня (`process.env.APPDATA`, `Split-Path -Parent $MyInvocation.MyCommand.Path`).
- Никаких захардкоженных путей пользователя (`C:\Users\...`).
- Исходные файлы Antigravity (`app.asar`) не модифицируются: работа ведется исключительно через CDP-инъекцию (порт 9222 / 9000).

## 🔄 Протокол бесшовного переключения между аккаунтами и сессиями (Handoff Protocol)

Когда пользователь начинает диалог с триггеров:
- `/resume`, `/handoff`, *«Подхвати проект»*, *«Где мы остановились»*, *«Сменил аккаунт»*
- Либо когда сессия начинается без явной истории в этом репозитории:

### Обязательный порядок действий агента:
1. **Первым делом прочитать `ACTIVE_STATE.md`** через `view_file`.
   - В нём зафиксировано: текущая версия, последний коммит, выполненные задачи, текущий фокус и следующий шаг.
   - **ЗАПРЕЩЕНО** начинать со сканирования всех файлов проекта или чтения словаря — это пустая трата токенов.
2. **При необходимости уточнить архитектуру**: прочитать компактный `BLUEPRINT.md`.
3. **Кратко поприветствовать пользователя**:
   - Назвать текущий статус (например: *«Подхватил проект на версии v1.1.0, ветка main»*).
   - Обозначить задачу, на которой остановились, и сразу предложить конкретное следующее действие.
4. **Фиксация перед завершением сессии**:
   - При завершении вехи или перед тем, как пользователь переключит аккаунт, обновить `ACTIVE_STATE.md` (раздел «Что сделано» и «Следующие шаги») и сделать коммит в Git.
